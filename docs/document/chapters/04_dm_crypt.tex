\chapter{dm-crypt 透明加密详细设计}

\section{概述}

dm-crypt 子系统提供透明的块级加密，确保写入物理存储设备的数据被加密，而读回的数据被实时解密。本实现专注于高性能的 AES-256-XTS 加密，并严格兼容 Linux 内核的 dm-crypt 表格式和 plain64 IV（初始化向量）生成机制。

在星绽操作系统中，dm-crypt 主要用于：
\begin{itemize}
    \item 保护根文件系统（rootfs）的机密性，防止物理介质被窃取后泄露数据。
    \item 为数据盘提供透明加密，使用户数据在持久化存储中始终保持密文状态。
    \item 作为 cryptsetup 工具的后端支撑，兼容 Linux 生态的加密卷管理流程。
\end{itemize}

\section{系统架构与数据流}

DmCryptDevice 充当任何实现 BlockDevice trait 的对象的包装器。它拦截 read block 和 write block 调用，在将数据传递给底层"下层"设备之前或之后执行密码学转换。

数据流的关键步骤如下：
\begin{enumerate}
    \item 应用程序或文件系统向 DmCryptDevice 发起 write block 请求。
    \item DmCryptDevice 根据逻辑块 ID 和 iv offset 计算对应的物理扇区号。
    \item 调用 Aes256XtsCipher 对数据进行加密，使用扇区号作为 plain64 IV。
    \item 将密文写入底层的 BlockDevice（如 VirtioBlkAdapter 或 FileBlockDevice）。
    \item 最终数据以密文形式持久化到物理存储介质。
\end{enumerate}

读路径是上述过程的逆操作：从底层设备读取密文，使用相同的扇区号进行解密，然后返回明文给调用者。

\subsection{Aes256XtsCipher——核心密码引擎}

这是核心密码引擎。它使用两个 AES-256 实例实现 XTS 模式：一个用于数据块，另一个用于微调（Tweak/IV）。

\textbf{密钥要求}：严格需要 64 字节（32 字节用于数据密钥，32 字节用于微调密钥）。如果密钥长度不正确，初始化将失败并返回错误。

\textbf{扇区大小}：固定为 512 字节，以兼容标准 dm-crypt 扇区单位。这是 Linux 内核 dm-crypt 的约定，保持一致性是实现逐字节兼容的前提。

\textbf{IV 生成（plain64）}：将 64 位扇区号编码到小端序 128 位 IV 的低半部分，然后由微调密钥进行加密。具体流程如下：
\begin{enumerate}
    \item 将扇区号（u64）转换为小端序字节序。
    \item 将转换后的 8 字节填入 16 字节缓冲区的低 8 位。
    \item 高位清零（plain64 不使用高位）。
    \item 微调密钥对完整的 16 字节 IV 进行加密，生成最终的微调值。
    \item 数据密钥与微调值配合，执行 XTS 模式的加密/解密操作。
\end{enumerate}

\subsection{DmCryptDevice——主设备映射目标}

主设备映射目标，负责管理扇区到块的算术运算，并确保 I/O 操作与底层设备的块大小对齐。

\textbf{扇区算术}：由于 BlockDevice trait 以块（通常为 4KiB）为单位操作，而 dm-crypt 以 512B 扇区为单位操作，DmCryptDevice 需要在两者之间进行转换：
\begin{enumerate}
    \item 根据 block id 和 iv offset 计算起始扇区号。
    \item 对于块内的每个扇区，依次调用密码引擎进行加密或解密。
    \item 处理扇区偏移与块边界的对齐问题，确保读写操作正确映射。
\end{enumerate}

\textbf{构造函数（from table）}：验证底层设备的块大小是否为 512B 扇区大小的倍数，并计算 data offset blocks。如果块大小不是 512 的倍数，初始化将失败。

\section{实现细节：扇区转换}

transform 函数是基于块的 BlockDevice 接口与基于扇区的 Aes256XtsCipher 之间的桥梁。

转换逻辑的核心要点：
\begin{itemize}
    \item 每个 4KiB 块包含 8 个 512B 扇区。
    \item 加密时，按扇区逐个处理，每个扇区使用其独立的扇区号作为 IV。
    \item data offset blocks 用于支持在设备开头预留空间（例如 LUKS 头部）。
    \item 实际物理块 ID = 逻辑块 ID + data offset blocks。
\end{itemize}

\subsection{交叉验证方法}

我们使用验证脚本进行逐字节兼容性验证：

\begin{enumerate}
    \item 在 Linux 系统中，使用 dmsetup 创建 aes-xts-plain64 映射器，写入特定位模式。
    \item 在 Rust 实现中，使用 dmctl crypt-table-fill 命令，使用完全相同的密钥和参数。
    \item 使用 cmp 命令比较两者生成的密文镜像。
    \item 验证通过的标准是：两个文件逐字节完全相同。
\end{enumerate}

\section{根文件系统加密方案}

为了实现对根文件系统的加密保护，系统在启动阶段执行以下流程：

\begin{enumerate}
    \item 内核引导程序传递启动参数。
    \item 星绽内核在初始化阶段解析这些参数，构建 DmBootConfig 结构体。
    \item aster-dm 组件实例化 VirtioBlkAdapter 包装物理设备，然后使用 DmCryptDevice 包装该适配器。
    \item initramfs 脚本挂载加密设备到 /newroot。
    \item 执行 pivot\_root 将根文件系统切换到加密卷。
    \item 系统从加密的根文件系统正常启动。
\end{enumerate}

\section{小结}

本章详细阐述了 dm-crypt 的设计与实现，包括 DmCryptTable 配置解析、Aes256XtsCipher 密码引擎、扇区算术转换、Linux 兼容性验证以及根文件系统加密方案。通过严格遵循 aes-xts-plain64 标准，并利用交叉验证确保与 Linux 内核的逐字节兼容，dm-crypt 为星绽操作系统提供了可靠的透明加密能力。
