\chapter{项目概述与背景}

\section{项目背景}

星绽操作系统（Asterinas）是一个采用创新性 Framekernel 架构的 Rust 操作系统，通过 OSTD 框架将内核核心组件运行于非特权级，实现了可信计算基（TCB）的最小化。依托 Rust 的所有权与生命周期机制，星绽从根源上规避了内存安全风险，同时在性能关键路径上保持高效执行。

在机密计算（Confidential Computing, CoCo）场景下，星绽计划作为 Guest Kernel 运行于可信虚拟机中。尽管内存数据受 TEE 保护，但持久化存储中的镜像（如 rootfs）仍存储在宿主机的不可信介质上，面临离线篡改、镜像替换、数据窃取等安全威胁。攻击者可借此植入后门或破坏系统完整性，危及整个信任链。

Linux 通过 Device Mapper 提供了 \texttt{dm-crypt}（透明数据加密）和 \texttt{dm-verity}（只读数据完整性校验）机制\cite{linux_dm_crypt,linux_dm_verity}，广泛用于全盘加密与安全启动，也是本项目进行功能对照与性能对比的同类参考实现。本赛题要求在星绽 OS 中，利用 Rust 的内存安全优势，自主实现类 \texttt{dm-crypt} 与 \texttt{dm-verity} 模块，填补星绽生态在存储安全方面的空白\cite{asterinas2024}。

\section{项目目标}

本项目在星绽操作系统上使用 Rust 编程语言实现 \texttt{dm-crypt} 与 \texttt{dm-verity} 功能，具体技术指标如下：

\begin{enumerate}
    \item \textbf{\texttt{dm-verity} 基础功能}：构建 SHA-256 哈希树\cite{fips180_4}，支持内核启动参数配置（如 \texttt{rootfs\_verity.scheme=dm-verity rootfs\_verity.hash=<hash>}），在系统启动时对根文件系统进行完整性验证。
    \item \textbf{\texttt{dm-crypt} 基础功能}：支持透明加解密 I/O 路径，兼容 Linux \texttt{aes-xts-plain64} 密码格式\cite{nist_sp800_38e}，作为后端支撑 \texttt{cryptsetup} 对加密卷的创建和管理\cite{cryptsetup}。
    \item \textbf{根文件系统加密}：使用 \texttt{dm-crypt} 加解密根文件系统，确保持久化数据的机密性。
    \item \textbf{性能与启动要求}：I/O 吞吐及延迟接近 Linux，\texttt{dm-verity} 不显著增加内核启动时间。
    \item \textbf{技术探索}：探索基于 Rust OS 的可信存储性能优化技术，如认证后哈希缓存、有界临时缓冲池和硬件加速（AES-NI）。
\end{enumerate}

当前版本已完成上述全部指标的用户态验证和星绽内核集成，并包含可审计的补丁序列和 KVM 五轮基准测试证据。

\section{双目标架构创新}

本项目的一个关键创新在于其\textbf{双目标架构}：核心逻辑被实现为一个与平台无关的 Rust 库（\texttt{dm} crate），该库同时服务于两个目标环境：

\begin{itemize}
    \item \textbf{用户态命令行工具（\texttt{dmctl}）}：用于演示、测试和基准测试，能够在宿主机上快速验证加密和完整性机制的正确性。
    \item \textbf{星绽内核集成（\texttt{aster-dm}）}：将相同的核心逻辑移植到内核空间，使星绽能够利用 \texttt{virtio-blk} 设备作为加密或完整性保护的卷，直接挂载受保护的文件系统（如 ext2）。
\end{itemize}

这种设计确保了用户态与内核态的逻辑一致性，使得测试和调试更加高效，同时也为后续的性能优化和功能扩展提供了统一的抽象基础。

\section{系统架构概述}

系统的核心抽象是 \texttt{BlockDevice} trait，它定义了统一的块级 I/O 接口（\texttt{read\_block} 和 \texttt{write\_block}）。不同的存储后端（如内存、文件、物理磁盘）均实现该 trait，而加密和完整性校验模块（\texttt{DmCryptDevice}、\texttt{DmVerityDevice}）则以“装饰器”模式包装下层设备，形成可堆叠的映射器链。

\section{文档结构}

本技术文档共分为九章和两个附录，结构如下：

\begin{itemize}
    \item \textbf{第2章 系统架构设计}：详细阐述 \texttt{BlockDevice} trait、可组合映射器链、模块分解及跨环境可移植性。
    \item \textbf{第3章 \texttt{dm-verity} 详细设计}：介绍默克尔树构建、单块校验路径、启动参数解析及只读强制策略。
    \item \textbf{第4章 \texttt{dm-crypt} 详细设计}：说明 \texttt{DmCryptTable}、AES-256-XTS 密码引擎、扇区算术及 Linux 兼容性验证。
    \item \textbf{第5章 性能设计与评测}：给出评测原则与真实性审计，报告 FIO、Filebench、SQLite 与启动耗时的分平台结果及实现侧性能设计。
    \item \textbf{第6章 测试与验收}：用户态单元测试、Linux 兼容性测试、Asterinas KVM 正确性测试与正式性能测试四层门禁及证据可复核性。
    \item \textbf{第7章 合规、来源与 AI 声明}：独立章节，严格遵循比赛要求，披露代码来源、开源协议、AI 工具使用情况及 Git 提交与开发迭代记录。
    \item \textbf{第8章 用户手册与部署指南}：提供从环境准备到编译、运行、配置的完整操作步骤与故障排查。
    \item \textbf{第9章 研发过程与工程收尾}：记录关键工程问题（块大小与扇区语义、BIO 生命周期、verity 信任边界）、补丁演进、渐进式保护路径与测试代码收口。
    \item \textbf{附录 A 术语表}：定义代码库中的关键术语。
    \item \textbf{附录 B \texttt{dmctl} 命令参考}：列出所有子命令的签名、示例和实现说明。
\end{itemize}
