\chapter{研发过程与问题解决记录}

\section{概述}

本章记录项目开发过程中遇到的核心技术难题及解决方案，并详细说明将 dm-crypt 和 dm-verity 集成到星绽内核的基础补丁序列。这些补丁构成了 \texttt{aster-dm} 组件的完整演进历史，可供评审逐行审计。

\section{核心技术难题及解决方法}

\subsection{Rust 所有权与 I/O 队列管理}

\textbf{问题描述}：在实现 \texttt{DmCryptDevice} 的 I/O 路径时，需要同时处理多个扇区的加解密操作。Rust 的所有权模型要求每个扇区的数据缓冲区有明确的所有者，导致借用检查器报错。尤其是在异步 BIO 完成回调场景中，多个请求共享同一状态槽时，生命周期管理变得复杂。

在早期的内核实现中，BIO 完成回调直接执行 AES-XTS 解密和上层完成，但回调上下文可能持有锁，导致潜在的锁竞争或死锁。

\textbf{解决方案}：
\begin{itemize}
    \item 采用 \texttt{Arc<Mutex<Vec<u8>>} 在多个扇区操作之间共享缓冲区。
    \item 利用 \texttt{try\_borrow\_mut} 避免死锁，在锁获取失败时返回错误而非等待。
    \item 对于热路径，使用有界临时缓冲池（\texttt{scratch\_pool}）预分配 \texttt{Vec}，通过池的 \texttt{take} 和 \texttt{recycle} 方法复用，避免在 I/O 路径中频繁分配和释放。
    \item 在实验性异步路径中，使用 \texttt{Arc<Mutex<Option<SubmittedBio>>>} 确保每个下层 BIO 的完成回调只触发一次上层完成，通过 \texttt{take()} 防止重复完成。
    \item 最终将解密操作从 VirtIO 硬中断回调迁移到专用内核线程（实验分支），减少锁持有时间。
\end{itemize}

\subsection{星绽 OSTD 框架 API 适配}

\textbf{问题描述}：星绽 OSTD 框架的块设备接口与预期不符，特别是 DMA 切片的访问方式。早期实现错误地使用虚拟地址操作 BIO 数据，导致加密和解密无法正确读写 DMA 物理缓冲区。

具体表现为：在对 \texttt{virtio-blk} 设备进行加密写入后，直接读取底层镜像发现数据未被正确加密，或者解密读回时数据损坏。

\textbf{解决方案}：
\begin{itemize}
    \item 重构 \texttt{VirtioBlkAdapter}，直接调用 DMA 切片接口（\texttt{segment.inner\_dma\_slice()}）进行读写，而非通过普通内存访问。
    \item 使用 \texttt{BioSegment::alloc\_bytes} 分配精确长度的下层 I/O 段，确保与加密扇区大小匹配，避免段对齐错误。
    \item 引入 \texttt{self\_test\_ext2\_magic} 自检机制，在启动时验证解密路径是否正确（检查 EXT2 魔数 \texttt{0x53EF}），确保 DMA 数据路径无误。
    \item 严格遵循 Rust 安全准则使用 \texttt{unsafe} 代码块，仅局限于调用底层驱动接口，并在安全抽象层之上构建加密逻辑。
\end{itemize}

\subsection{DMA 切片与 BIO 路径验证}

\textbf{问题描述}：加密逻辑操作的是 BIO 段的虚拟地址，而非实际的 DMA 物理缓冲区。在星绽内核中，BIO 段的数据可能驻留在 DMA 缓冲区中，不能通过普通内存访问直接操作。

此外，BIO 的读写方向（\texttt{BioDirection::FromDevice} 和 \texttt{ToDevice}）需要正确设置，否则 DMA 切片的数据方向错误会导致数据损坏。

\textbf{解决方案}：
\begin{enumerate}
    \item 使用 DMA 切片接口访问 BIO 段（\texttt{segment.inner\_dma\_slice()}），而非 \texttt{segment.read\_bytes}/\texttt{write\_bytes}。
    \item 确保加密操作直接读写 DMA 缓冲区，而非通过中间 \texttt{Vec} 拷贝（除必要的加解密转换外）。
    \item 写路径：从调用方 DMA 段复制明文到临时缓冲区，加密后写入下层 BIO 的 DMA 段。
    \item 读路径：从下层 DMA 段复制密文到临时缓冲区，解密后写回调用方的 DMA 段。
    \item 引入自检机制验证解密路径，补丁 0002 中实现 \texttt{self\_test\_ext2\_magic} 检查 EXT2 魔数，确保读写方向和 DMA 访问正确。
\end{enumerate}

\subsection{根文件系统切换（pivot\_root）与映射器生命周期}

\textbf{问题描述}：Asterinas 的 \texttt{pivot\_root} 要求当前根文件系统具有挂载父节点，而 initramfs 的特殊 rootfs 挂载不具备此条件，直接切换会失败。

此外，映射器设备在 \texttt{pivot\_root} 后需要保持可用，且 initramfs 的工具链（如 \texttt{poweroff}）在切换后仍需可访问。

\textbf{解决方案}：
\begin{enumerate}
    \item 采用两阶段 \texttt{dm-root} 模式（补丁 0003）：
        \begin{itemize}
            \item 第一阶段：initramfs 先将自身根目录通过 \texttt{mount --bind} 挂载到 \texttt{/bootstrap-root}，同时绑定挂载 \texttt{/dev} 到 \texttt{/bootstrap-root/dev}。
            \item 使用 \texttt{chroot /bootstrap-root} 进入该挂载点，然后执行第二阶段 init（传递 \texttt{dm-root-stage2} 参数）。
            \item 第二阶段：将映射器设备挂载到 \texttt{/newroot}，执行 \texttt{pivot\_root /newroot /newroot/.initramfs}，将受保护根文件系统切换为系统根。
        \end{itemize}
    \item 切换后，initramfs 工具链保留在 \texttt{/.initramfs} 目录下，确保关机等操作仍然可用。
    \item 映射器设备在 \texttt{pivot\_root} 前已注册到块设备子系统，切换后继续存在，不受根文件系统切换影响。
    \item 在切换前验证 \texttt{/etc/dm-verity-proof} 文件是否存在，确保受保护根文件系统正确挂载。
\end{enumerate}

\section{内核集成补丁说明}

以下补丁序列位于 \texttt{asterinas\_port/patches/}，基于 Asterinas commit \texttt{c6284a9106f5a4c87deb7c8a990af6211dc5f540}。

\subsection{补丁 0001：组件集成与目标定义}

\textbf{目的}：将 \texttt{aster-dm} 组件引入星绽构建系统，实现基础 mapper 框架。

\textbf{实现细节}：
\begin{itemize}
    \item \textbf{组件注册}：将 \texttt{aster-dm} 添加到 \texttt{Cargo.toml}（workspace members）和 \texttt{Components.toml}，使内核构建系统包含该组件。
    \item \textbf{分区扫描抑制}：在 \texttt{aster-block} 的 \texttt{BlockDevice} trait 中增加 \texttt{supports\_partition\_scan} 方法，允许 dm-verity 设备跳过分区扫描，避免误解析哈希区为分区表。
    \item \textbf{目标抽象}：定义 \texttt{DmTarget} 枚举（位于 \texttt{device.rs}），封装 \texttt{Passthrough}、\texttt{Crypt}（含 \texttt{AesXtsCipher}）和 \texttt{Verity}（含 \texttt{VerityTarget}）三种目标。
    \item \textbf{设备结构}：实现 \texttt{DmDevice}，持有下层设备引用和目标，通过 \texttt{enqueue} 方法分发 BIO 到对应的处理函数（\texttt{process\_passthrough}、\texttt{process\_crypt}、\texttt{process\_verity}）。
    \item \textbf{核心模块}：引入 \texttt{crypto.rs}（AES-256-XTS 实现）、\texttt{sha256.rs}（纯 Rust SHA-256）、\texttt{verity.rs}（on-disk hash tree 校验）。
    \item \textbf{启动参数}：定义 \texttt{dm\_crypt.*}（\texttt{device}、\texttt{name}、\texttt{key}）和 \texttt{rootfs\_verity.*}（\texttt{scheme}、\texttt{device}、\texttt{name}、\texttt{hash}、\texttt{data\_blocks}、\texttt{hash\_start}）命令行参数解析。
    \item \textbf{initramfs 增强}：修改 initramfs 脚本以检测并挂载 \texttt{/dev/vdc} 上的 dm-verity mapper，验证 \texttt{/etc/dm-verity-proof} 文件。
\end{itemize}

\subsection{补丁 0002：BIO 路径验证与自检}

\textbf{目的}：修复 DMA 切片访问方向错误，并增加启动时自检机制。

\textbf{实现细节}：
\begin{itemize}
    \item \textbf{DMA 切片访问}：使用 \texttt{segment.inner\_dma\_slice()} 替代原有 \texttt{segment.read\_bytes} 和 \texttt{segment.write\_bytes}，确保 DMA 缓冲区正确读写。
    \item \textbf{Ext2 超级块自检}：实现 \texttt{self\_test\_ext2\_magic} 方法，检查偏移量 1080（1024+56）处的 EXT2 魔数 \texttt{0x53EF}，验证解密路径。
    \item \textbf{启动集成}：内核 \texttt{init} 函数在注册映射器后调用自检，失败则 panic 并输出 \texttt{[dm-test] FAIL} 日志。
    \item \textbf{错误处理}：增加 \texttt{DmError::InvalidData} 错误类型，用于自检失败。
    \item \textbf{测试脚本}：新增 \texttt{tools/run\_dm\_crypt.sh} 和 \texttt{tools/run\_dm\_verity.sh}，支持 KVM 测试，并在 initramfs 中输出 \texttt{[dm-test] PASS/FAIL} 日志。
    \item \texttt{supports\_partition\_scan} 默认返回 \texttt{false}，确保所有 dm 设备跳过分区扫描，避免误解析。
\end{itemize}

\subsection{补丁 0003：根文件系统 Pivot\_root 切换}

\textbf{目的}：修改 initramfs 脚本，支持切换到受保护的根文件系统。

\textbf{实现细节}：
\begin{itemize}
    \item \textbf{参数解析}：解析 \texttt{dm-root} 命令行参数，获取映射器设备名（如 \texttt{/dev/dm-crypt0} 或 \texttt{/dev/dm-verity0}）。
    \item \textbf{两阶段切换}：
        \begin{enumerate}
            \item 第一阶段：initramfs 检测到 \texttt{dm-root} 参数后，将当前根目录绑定挂载到 \texttt{/bootstrap-root}，同时绑定挂载 \texttt{/dev}。
            \item 使用 \texttt{chroot /bootstrap-root /init dm-root-stage2 <device>} 进入第二阶段。
            \item 第二阶段：将映射器设备挂载到 \texttt{/newroot}，检查 \texttt{/newroot/etc/dm-verity-proof} 是否存在。
            \item 执行 \texttt{pivot\_root /newroot /newroot/.initramfs}，将 initramfs 移动到 \texttt{/.initramfs}。
        \end{enumerate}
    \item \textbf{切换后验证}：检查 \texttt{/etc/dm-verity-proof} 和 \texttt{/.initramfs} 目录是否存在，确保受保护根文件系统正确激活。
    \item \textbf{initramfs 保留}：切换后 initramfs 工具链保留在 \texttt{/.initramfs} 目录，便于关机等操作（执行 \texttt{/.initramfs/bin/busybox poweroff -f}）。
    \item \textbf{启动脚本更新}：修改 \texttt{tools/run\_dm\_crypt.sh} 和 \texttt{tools/run\_dm\_verity.sh}，增加 \texttt{--init-args="dm-root /dev/<mapper> /.initramfs/bin/true"}。
\end{itemize}

\subsection{补丁 0004：Runtime 控制面与 cryptsetup 兼容}

\textbf{目的}：实现 Linux \texttt{dm\_ioctl} 控制接口，支持动态创建/删除 mapper，为 \texttt{cryptsetup} 提供基础。

\textbf{实现细节}：
\begin{itemize}
    \item \textbf{控制设备}：在 \texttt{/dev/mapper/control} 实现 \texttt{DmControlDevice}（位于 \texttt{kernel/src/device/misc/dm\_control.rs}），支持以下 ioctl：
        \begin{itemize}
            \item \texttt{DM\_VERSION}、\texttt{DM\_LIST\_VERSIONS}
            \item \texttt{DM\_DEV\_CREATE}：创建 runtime mapper
            \item \texttt{DM\_TABLE\_LOAD}：加载 crypt table（支持 \texttt{aes-xts-plain64}）
            \item \texttt{DM\_DEV\_SUSPEND}：激活 mapper（resume）
            \item \texttt{DM\_DEV\_STATUS}：查询状态
            \item \texttt{DM\_DEV\_REMOVE}：删除 mapper
        \end{itemize}
    \item \texttt{DmCryptTable} 解析增强：支持选项计数（\texttt{allow\_discards}、\texttt{no\_read\_workqueue} 等）。
    \item \textbf{Runtime 映射器管理}：在 \texttt{runtime.rs} 中实现 \texttt{create\_runtime\_mapper}、\texttt{load\_runtime\_crypt\_table}、\texttt{activate\_runtime\_mapper}、\texttt{remove\_runtime\_mapper} 函数，管理动态 mapper 生命周期（状态：Empty、Loaded、Active）。
    \item \textbf{设备节点创建}：成功激活后自动在 \texttt{/dev/mapper/} 下创建设备节点（通过 \texttt{add\_node}）。
    \item \textbf{性能 procfs}：添加 \texttt{/proc/dm-crypto-backend}（显示 AES 后端）、\texttt{/proc/dm-verity-stats}（显示 verity 计数器）。
    \item \textbf{AES-NI 支持}：通过 \texttt{ostd::arch::x86::aesni} 模块，在保存/恢复 FPU 状态的前提下使用 AES-NI 指令；通过 \texttt{cpufeatures} 检测 CPU 支持。
    \item \textbf{密钥清除}：在 \texttt{remove\_runtime\_mapper} 和 \texttt{activate\_runtime\_mapper} 中清除密钥（\texttt{table.key.fill(0)}），避免密钥残留在内存中。
\end{itemize}

\subsection{补丁 0005：性能优化与可配置基准}

\textbf{目的}：加入认证后 hash cache、有界临时缓冲池、已认证路径捷径等优化，并提供可配置 fio 基准。

\textbf{实现细节}：
\begin{itemize}
    \item \textbf{有界临时缓冲池}：在 \texttt{CryptTarget} 中实现 \texttt{CryptScratchPool}，支持 \texttt{take} 和 \texttt{recycle}，大小由启动参数 \texttt{dm\_crypt.scratch\_pool} 控制（默认 32）。
    \item \textbf{认证后 hash cache}：在 \texttt{VerityTarget} 中实现有界 FIFO 缓存（\texttt{VerifiedHashBlockCache}），只插入已完整认证的 hash block。
    \item \textbf{已认证路径捷径}：当缓存命中时，直接比对当前数据摘要与缓存块，跳过上层哈希重算，增加 \texttt{auth\_shortcuts} 计数器。
    \item \textbf{BIO 数据复用}：对 4 KiB 对齐的读请求，直接复用已完成 BIO 的数据块，避免再次读取（\texttt{verify\_segments} 方法）。
    \item \textbf{可配置基准}：\texttt{tools/run\_dm\_crypt\_bench.sh} 和 \texttt{tools/run\_dm\_verity\_bench.sh} 支持 \texttt{DM\_BENCH\_*} 环境变量，包括 rw、bs、qd、size、runtime、runs、ramp 等。
    \item \texttt{test/initramfs/src/init} 增加 \texttt{dm-bench} 模式，支持在 KVM 客体中自动运行 fio 矩阵并输出串口日志。
\end{itemize}

\subsection{补丁 0006：性能阶段归因与正式基准合同}

\textbf{目的}：添加细粒度阶段计时，固化正式 256 MiB 基准合同。

\textbf{实现细节}：
\begin{itemize}
    \item \textbf{阶段统计}：在 \texttt{device.rs} 和 \texttt{verity.rs} 中埋点，使用 \texttt{DmAtomicPerformanceStats} 原子计数器记录以下阶段：
        \begin{itemize}
            \item dm-crypt：\texttt{validation}、\texttt{scratch}、\texttt{copy}、\texttt{crypto}、\texttt{lower\_wait}
            \item dm-verity：\texttt{validation}、\texttt{lower\_wait}、\texttt{data\_sha256}、\texttt{cache\_lookup}、\texttt{hash\_wait}、\texttt{hash\_sha256}、\texttt{digest\_compare}、\texttt{cache\_insert}
        \end{itemize}
    \item \texttt{/proc/dm-performance-stats}：输出累计计数器，每轮 fio 前后读取，由汇总器（\texttt{summarize\_dm\_performance\_stages.py}）计算差值。
    \item \textbf{正式合同}：\texttt{run\_formal\_dm\_benchmark.sh} 强制：
        \begin{itemize}
            \item 内核构建：\texttt{release-lto}
            \item 虚拟化：KVM、CPU=host、1 vCPU、8 GiB
            \item 块设备：virtio-blk，264 MiB 容器，前 256 MiB 数据区
            \item fio：read、4 KiB、sync、direct=1、QD1
            \item 时长：2s ramp + 10s runtime
            \item 重复：raw/target 交替顺序，各五轮
            \item 阶段统计：\texttt{dm.perf\_stats=1}
        \end{itemize}
    \item \textbf{metadata 校验}：汇总器严格核对 git commit、dirty 状态、镜像 SHA-256、fio 参数，不一致则拒绝生成结果表。
    \item \textbf{观察者开销校准}：\texttt{run\_dm\_stats\_calibration.sh} 对比 stats=0/1 的吞吐差异，确保计时开销 < 3\%。
\end{itemize}

\section{实验性优化探索}

在正式基线之外，我们还进行了以下实验性探索：

\subsection{异步 BIO 完成路径}

实验分支 \texttt{codex/dm-async-bio} 将 dm-crypt 的下层 BIO 从同步 \texttt{submit\_and\_wait} 改为异步完成回调。实现要点：
\begin{itemize}
    \item 使用 \texttt{Bio::submit\_without\_wait} 提交下层 BIO。
    \item 完成回调中执行 AES-XTS 解密、scratch 归还和上层 BIO 完成。
    \item 使用 \texttt{Arc<Mutex<Option<SubmittedBio>>>} 保证上层 BIO 只完成一次。
\end{itemize}

五轮 KVM 测试显示 raw 和 dm-crypt 吞吐同时提升约 49\%，但 raw 归一化后的效率变化为 -0.62\%，因此未合入基线。该实验证明了 I/O 路径仍有优化空间，但收益主要来自宿主机环境波动，非代码改动。

\subsection{完成队列与专用 worker}

后续分支 \texttt{codex/dm-completion-worker} 将解密从 VirtIO 硬中断回调迁到专用内核线程：
\begin{itemize}
    \item 中断回调只记录完成状态并入队（无分配）。
    \item 专用 worker 在普通线程上下文执行解密和上层完成。
\end{itemize}

该改动使 32-job 并发从停滞变为五轮稳定完成。进一步批量出队（commit \texttt{6b3ca2407}）和每 CPU worker（commit \texttt{9a3483571}）优化分别取得：
\begin{itemize}
    \item 批量出队（1 vCPU）：QD1 和 32-job 的配对 raw 保持率分别 +7.66\% 和 +7.07\%。
    \item 每 CPU worker（4 vCPU）：32-job 完成队列占比从 29.15\% 降至 6.55\%，p95 降低 43.62\%；但 QD1 保持率下降 4.10\%。
\end{itemize}

这些实验证据证明并发路径仍有优化空间，但因 QD1 有退化，暂不合入正式基线。

\section{小结}

本章详细记录了项目研发过程中遇到的四大核心技术难题及解决方案，深入阐述了 6 个基础内核集成补丁的设计思路和实现细节，并展示了五阶段渐进式保护路径和实验性优化探索。通过补丁 0002 的 Ext2 超级块自检机制和补丁 0003 的 \texttt{pivot\_root} 切换，系统能够在启动时验证加解密路径的正确性，并安全地切换到受保护的根文件系统；后续功能与性能收尾以补丁 0004--0006 固化，最终形成可复核、可量化的完整技术交付。实验性优化成果为未来改进指明了方向。
